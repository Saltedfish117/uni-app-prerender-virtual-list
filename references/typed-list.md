# 分类实测高度列表

适合有限种结构，例如组头、单行卡片、双行卡片。类型代表高度结构，不代表业务分类；同一类型必须在当前宽度下具有相同总高。

## 建模与预渲染

- 数据适配层完成筛选、分组、排序，再生成 `{ key, type, data }`。只传用于展示的值，完整原始对象保存在页面索引中。
- 对影响布局的结构建立类型，例如是否有第二行、是否有固定动作区。不要把业务状态枚举不加分析地直接当作高度类型。
- 每类临时渲染一个与真实行相同的代表，批量测量形成 `heightByType`；测量与正式行共享 CSS 和宽度。
- 高度分类不能靠“最长字符串”保证正确：不同字符宽度和换行点会造成更高的短文本。通过固定行数、截断或明确高度建立等高契约。
- 先得到完整有效高度表，再 `replaceLayout`；新增类型未测量时显示等待/重试状态，不能用零高度或随意常量替代。

## 布局与滚动

按 `gapBefore` 和类型高度累加 `top/bottom`，二分计算窗口边界。所有间距显式传入布局，行组件不另加会脱离测量的垂直 margin。容器总高只包含已加载节点，不用服务端总条数伪造未知高度的占位。

可见范围中包含多种组件时保持稳定 key，不用窗口索引。模板采用 key 数组与节点映射，详见 [原生绑定](integration.md#窗口的原生绑定)。预渲染与正式模板的显隐条件要同步修改；仅更新其中一套会导致高度漂移。

## 失效与局限

宽度、字体、类型结构或行内布局规则变化，重新测量并原子替换。旧测量结果、旧 finally 和旧跳转回调都不能覆盖新任务。

传入高度表即视为明确请求重排；无论是新对象还是同一引用，都要让控制器读取新数值。仍然推荐创建新高度表，避免外部修改与内部缓存耦合。

本模式不等于逐条动态测高。内容可随时增高的列表需要独立的行高缓存、增量偏移维护和锚点保位方案，不应直接复制本模板后宣称已支持。
