# 快速滑动空白：诊断、同步与验收

## 先保留现场

空白发生后先截屏、读取状态，不要立刻刷新、重测或调用整窗 setData；这些操作可能消除现场。记录滚动所有者、实际原生 scrollTop、最后收到的事件、适配器原始/局部位置、视口高、总高、布局版本和当前窗口。全部示例数值应使用合成数据。

| 证据 | 优先检查 |
| --- | --- |
| 样本宽度与列表宽度不同 | 样本包含块、padding、rpx 舍入；按正式列表继承宽度 |
| 原生已滚到末尾，适配器仍在中部 | 末次事件未及时到达；有界原生回读与立即刷新 |
| 两种位置相同，窗口未覆盖视口 | 坐标换算、类型高度、间距、旧节流或布局版本 |
| JS 窗口和原生页面数据正确，实际节点 top/内容错误 | 编译后 key、对象数组增量更新与节点复用 |
| 外层节点 top 正确，但卡片内容溢出或留空 | 类型高度契约、内部样式、异步图片/文本尺寸 |

缓冲区只能容纳暂时延迟；若停稳后仍持续空白，不应先增大缓冲或减小节流值。不同问题可能同时存在。

## 同时检查数据与实际节点

等待视图提交后，在同一 selector query 中读取列表 rect、滚动容器 rect/offset 和全部 `.virtual-node` 的 `dataset`、rect、size。按 `data-node-key` 查当前节点映射，再比较：

```js
const expectedTop = listRect.top + node.rect.top;
const expectedHeight = node.rect.height;
const topError = actualRect.top - expectedTop;
```

这些 rect 均为视口坐标；不要再减一次 scrollTop。使用像素容差而非严格浮点相等。若查询期间布局、窗口或滚动版本变化，丢弃该轮比较并重新采样。检查每个节点的身份、位置、高度和内容，不能只看首尾范围；内部可能有错位、重叠或缺口。

`fields({ rect:true, size:true, dataset:true })` 可用于取实际节点。避免同一个结果再请求 `computedStyle:['top']`：CSS top 字符串可能覆盖数值 rect.top。若要检查内联 style/transform，另读属性，分别命名。原生页面 `data.visibleNodes` 正确也不能代替实际节点 rect 检查。

若确认样式残留，使用 `buildKeyedWindow` 的 key 数组与内容映射。不要用窗口索引 key、每次清空后重挂载、取消全部 diff、全量列表渲染或直接每帧原生 setData 作为生产修复。诊断时单次完整窗口提交能验证“重新提交是否恢复”，但不能据此证明控制器或滚动事件就是根因。

## 原生滚动同步工具

`assets/scroll-view-sync.js` 导出 `createScrollViewSync(options)`。与 `uni-list-adapter.js` 一起复制，容器示例已接入。

| 配置 | 说明 |
| --- | --- |
| `readOffset()` | Promise/同步返回该 scroll-view 的实际原生 scrollTop；不可返回绑定命令值 |
| `applyOffset(actual)` | 调用 `adapter.syncScroll(actual)`，统一原始/局部位置并立即刷新 |
| `isActive()` | 页面显示、布局可用且未卸载 |
| `onError(error)` | 查询失败、超时或回顶失败时接入现有重试入口 |
| `quietMs = 120` | 事件静默后首次查询、后续采样间隔，须大于 0 |
| `maxSamples = 8` | 每轮最多查询次数，至少 2 次；连续两次相差不超过容差则停 |
| `queryTimeoutMs = 800` | 单次查询或回顶视图提交的最长等待时间 |
| `tolerance = 1` | 稳定及回顶校验的 px 容差 |
| `clock` | 可注入计时器用于确定性测试，正常接入可省略 |

这些默认值是调试起点。不要把短暂两次稳定读数视为所有设备惯性已结束的证明；仍需实际手势验证，必要时按设备调整稳定判定。单轮达到采样上限时保留最后有效位置并停止，新事件可启动下一轮。

方法：

- `schedule()`：每次事件正常交给 adapter 后调用，重置静默等待并作废旧查询。
- `reconcile()`：立即开始一轮有界查询。在触底、布局成功及数据追加后的视图提交后调用。触底校正应放在 `noMore/loading` 判断之前，已加载全部数据也需要校正。
- `resetToTop({getBoundTop,setBoundTop,nextTick})`：先等待已有视图提交，再切换原生绑定命令并等待提交，查询直到实际位置接近 0，再同步适配器。成功返回 true；失败或过期返回 false。
- `cancel()` / `dispose()`：作废版本、清计时器并立即结束挂起等待。原生查询不可取消时，晚返回的值/错误也不会写回。

`schedule` 和 `reconcile` 仅在连续两次位置稳定时返回 true；达到采样上限返回 false，但已应用每次有效位置。查询错误走 onError；旧任务返回 false 且不报错。主动回顶期间，滚动事件仍可更新 adapter，工具忽略由此触发的采样请求，避免回顶自己取消自己。

新筛选、数据/布局替换前先 cancel，提交后再 reconcile；页面 hide/unload 必须取消或销毁。不要把查询塞进每一帧滚动事件，或让 timer 永久轮询。对页面滚动，保持其独立的 owner 查询与生命周期，不直接复制 scroll-view 的 selector。

## 筛选先回顶再刷新

仅在需求要求筛选回顶时使用。普通翻页、取消草稿、导出或 Tab 切换是否保位由页面规则决定，工具不替页面选择。

1. 新筛选分配请求/刷新版本，使旧请求、旧原生查询失效，并暂停触底加载。
2. scroll-view 绑定 `scroll-top`，关闭回顶动画。先等待上一轮视图提交，防止连续确认在同一批次把两次切换合并为未变化的值；检查版本后，通过不同的近零命令触发重复回顶：

   ```js
   this.scrollTop = this.scrollTop === 0 ? 0.1 : 0;
   ```

3. 等待视图提交，真实回读该容器位置，按有限次数/超时确认接近顶部。不要仅把 JS 命令值设为 0 就认为成功，也不要依赖“当前位置 → nextTick → 0”能触发每次回顶。
4. 同步 adapter 原始位置，立即刷新控制器以清掉旧节流任务。保留 `rawScrollTop - listTop` 的负数局部位置，不强制局部位置为 0。
5. 只有最新版本且确认成功，才清空旧列表、重置分页、请求第一页。每个 await 后再次校验请求版本和页面状态；旧响应不可写回。
6. 数据与新总高提交后再校正一次，处理原生因内容缩短自动夹取的位置。失败走现有重试入口，不能继续按未确认位置刷新；hide/unload 取消待执行流程。

容器模板用本地“全部/偶数条目”展示这一顺序，没有业务接口。真实请求竞态、分页和权限逻辑由宿主实现，不从示例虚构字段。

## 验收矩阵

| 场景 | 要验证的结果 |
| --- | --- |
| 列表中下部确认筛选，结果变短/长/空 | 确认原生回顶和 adapter 同步后才开始第一页；新布局无旧节点 |
| 连续两次筛选、旧请求/查询晚返回 | 仅最新版本更新视图；隐藏和卸载后无回写 |
| 一次真实快速滑动，让惯性到末尾 | 停稳后原生与 adapter 一致；窗口覆盖、逐节点位置和截图均正确 |
| 已无更多数据、触底追加同组/新组 | 仍校正原生位置；追加不误触回顶；组头/尾部补高正确 |
| 反向快速滑动、分组跳转、返回页面 | 节流尾次、组状态和实际最终位置正确，无重叠或持续缺口 |
| 不同宽度、不同高度类型、重试测量 | 样本同宽、类型高一致；失败有重试且不会用错误几何继续展示 |

保留修复前后截图、逐节点偏移比较和所用平台/编译器版本。分别报告 Node、模板编译、开发者工具程序滚动、人工惯性手势、Android、iOS 的结果。SDK scrollTo 或合成 touch 事件未引发原生惯性时，只能算程序定位/事件测试。
